Keyweb

Privacy policy

28 September 2026

Keyweb keeps your passwords, notes and sign-in codes on your devices. If you turn on backup, it also keeps an encrypted copy in your Google Drive, so another device signed in to the same Google account can open the same vault. Sharing a keyring works the same way: the file sits in your Drive, encrypted for the people you add.

There is no Keyweb account, and no Keyweb server that stores the vault. This page is part of the website. The Android app does the same job and is covered by the same policy.

On your device

The vault is stored in this browser, or in the app's private storage on Android. It is scrambled with a key held by your face, fingerprint, PIN or recovery code. Without one of those, the copy on the device cannot be read. Keyweb never receives the face or the fingerprint. The device checks them, and only then releases the key.

A few preferences sit beside the vault and are not part of it: text size, light or dark, how long Keyweb waits before locking, sort order, and which Drive file this browser is using.

A sign-in code you scan is read on the device. The camera picture is not uploaded. The password you type to open a KeePass file is used once, to copy from that file, and is not kept. Keyweb does not write back to the KeePass file.

The Android app turns off Android's backup of app data, so the vault is not included in Google's backup of the phone. A Drive file you chose to make is a separate copy. On launch, the Android app also asks GitHub whether a newer version has been published. That request tells GitHub the device's IP address and that Keyweb is installed. It does not include the vault or a Google account.

Google Drive

Backup and sharing are optional. When you use them, Keyweb asks Google for two permissions and no others.

  • Files Keyweb creates, and files you pick (drive.file). Keyweb cannot browse the rest of your Drive. It creates a folder named Keyweb and a file named keyweb-vault-v1.json. That file is the same sealed vault the device holds. Shared keyrings go in a folder named Keyweb shared keyrings. Each one is encrypted for the people on that keyring, not with the key that opens everything else. A KeePass file, or a keyring someone has shared with you, stays out of reach until you choose it in Google's file picker.
  • A hidden folder only this app can use (drive.appdata). It holds your sharing key, wrapped so only your own devices can open it. A second browser or phone signed in to the same Google account reads that copy, which is how both devices count as the same person when a keyring is shared. The folder does not appear in your Drive file list. It is not your passwords.

Keyweb also reads the name, size and last-changed time of those files, so two of your devices can tell which copy is newer. Google stores the files. Google can see the folder names, the file names, and which Google accounts a shared file is shared with. Google cannot read the passwords inside. There is nowhere else for them to be sent.

While you are signed in, Keyweb holds a short-lived access token in memory and sends it only to Google.

Email addresses

To share a keyring you type the other person's email address. Keyweb gives that address to Google Drive, which is how Drive can hand them the file. Keyweb remembers it on your device so the screen can show a name. That list is not part of the encrypted file in Drive, and it is not sent anywhere else.

Keyweb also asks Google for the email address of the account you signed in with. If Google returns one, it is written on the link you send, so the other person can see who it came from. The keyring is tied to a key, not to that address. If Google does not return an address, the link has none.

You send the link yourself. It does not contain passwords. It can contain your email and the keyring's name, as labels, and the public keys the share needs. Anyone you send it to can read those labels, and so can anyone they pass it to. Opening the link loads this site, so the address of the link is part of that request.

Filling in a password

On Android, if you turn autofill on, Keyweb types a password into the app or site you are signing in to. That is the only place it goes.

This website

Keyweb does not sell information, show ads, or send the vault to an analytics or crash service. The site is hosted on GitHub Pages. Loading it is a request to GitHub, which receives the ordinary facts of that request, such as your IP address. The vault is not part of the request.

Taking access away

You can delete a Drive backup from Settings. Google keeps a deleted Drive file in the bin for about thirty days.

Clearing this site's data, or uninstalling the Android app, removes the copy on that device. It does not remove files already in Drive.

You can withdraw Keyweb's permission from your Google Account settings. After that, Keyweb cannot reach Drive. Files already there stay until you delete them.

Google's rules for this data

Keyweb's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements. That information is used to keep the backup you asked for and to share the keyrings you ask to share. It is not used for advertising, and it is not sold.
